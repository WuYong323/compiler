## 精炼段

编译器的本质是**语义保持的翻译**：把一种语言（源语言）变成另一种语言（目标语言），且保证"意思不变"。它按阶段划分为前端（词法/语法/语义）、中端（IR 与优化）、后端（代码生成/寄存器分配）。学编译原理的价值在于：它是所有"理解程序、转换程序、加速程序"技术的共同底座——从你写过的 vLLM 到 PyTorch 的 JIT、TVM/MLIR 的深度学习编译，全是编译思想的延伸。本篇建立全局观，之后每一篇都是这条流水线上的一个工位。

## 1. 什么是编译器

**编译器（compiler）**：读入一种语言写的程序，输出**另一种语言**的等价程序。

**一句话直觉**：编译器就是一个"翻译官"。中文 → 英文的翻译官保证译文表达同样的意思；编译器保证 `x + y * 2` 翻译成机器指令后，算出来的结果和数学规定一致。

### 1.1 编译器 vs 解释器（先分清这两个）

| | 编译器 (Compiler) | 解释器 (Interpreter) |
|---|---|---|
| 工作方式 | 一次性翻译成目标语言，之后**反复执行**产物 | **边读边执行**，不产生持久产物 |
| 类比 | 把整本英文书翻译成中文书，读者读中文书 | 同声传译，说一句译一句 |
| 例子 | gcc、clang、rustc、我们的 coolc | Python (CPython)、早期的 BASIC、JS 老引擎 |
| 速度 | 执行期快（翻译成本一次性付出） | 执行期慢（每次都要重新理解） |

**现代真相**：二者界限早已模糊——Java/Python/JS 用 **JIT（即时编译）**：先解释执行，把热代码**运行时编译**成机器码再执行（doc 13 详讲）。这就是"编译思想"渗透到一切语言运行时的证据。

### 1.2 翻译器全景（CS143 第一课的图）

```
           ┌──────────────┐
           │  翻译器 (Translator)  │
           └──────┬───────┘
        ┌─────────┴─────────┐
        ▼                   ▼
   ┌─────────┐         ┌─────────┐
   │ 编译器   │         │ 解释器   │
   │(compiler)│        │(interpreter)│
   └─────────┘         └─────────┘
```

编译器本身又可按"源语言/目标语言关系"细分，但 CS143 关注的是**通用编译器**：源语言是高级语言（Cool），目标语言是低级表示（LLVM IR，最终可降到机器码）。

## 2. 编译器的两大核心难题（这决定了为什么分这么多阶段）

编译器要同时回答两个问题，而它们**很难一步完成**：

1. **分析（Analysis）**：这个程序**是什么意思**？（源语言侧）
2. **综合（Synthesis）**：如何**构造**出等价的目标程序？（目标语言侧）

**为什么要分阶段？** 类比装修：你不会让一个人"从毛坯直接住进精装房"——要拆成 水电 → 泥瓦 → 木工 → 油漆，每步只做一件事、只依赖上一步的成果。编译器分阶段的原因完全一样：

- **每阶段只解决一个问题**，逻辑简单、可测试、可复用；
- **前端与后端解耦**：换个源语言（Cool → C），只要重写前端；换个目标（x86 → ARM），只要重写后端。中端 IR 是"通用货币"。

> 这就是现代编译器的**三段式结构**，是 CS143 贯穿始终的主线。

## 3. 三段式结构 + 各阶段详解

### 3.1 全景

```
Cool 源码
   │  前端 Front-End（理解"源语言说了什么"）
   ▼
词法分析 ──► 语法分析 ──► 语义分析
 Token流       AST          带类型AST
   │  中端 Middle-End（与语言/机器都无关的优化）
   ▼
中间表示 IR（SSA）──► 分析与优化
   │  后端 Back-End（面向"目标机器"）
   ▼
代码生成 ──► 寄存器分配 ──► 目标代码 (LLVM IR / 机器码)
```

### 3.2 各阶段：输入 → 输出 → 一句话

| 阶段 | 输入 | 输出 | 干什么 | 类比 |
|---|---|---|---|---|
| ① 词法分析 Lexing | 字符流 `i f  ( x > 3 )` | Token 流 `IF ( ID > INT )` | 把字符聚成"词"，丢弃空白/注释 | 分词 |
| ② 语法分析 Parsing | Token 流 | 抽象语法树 AST | 按文法检验句子结构 | 划主谓宾 |
| ③ 语义分析 Semantic | AST | 带类型 AST + 符号表 | 检查类型、作用域、名字是否合法 | 检查病句 |
| ④ 中间表示 IR | 带类型 AST | 三地址码/SSA | 把高级结构降成统一低级形式 | 打草稿 |
| ⑤ 优化 Optimize | IR | 更优 IR | 消除冗余，等价变换 | 润色 |
| ⑥ 代码生成 Codegen | IR | 目标代码 | 映射到目标机器指令 | 定稿翻译 |
| ⑦ 寄存器分配 | 目标代码 | 分配好寄存器的代码 | 让热点变量住进寄存器 | 安排座位 |
| ⑧ 运行时 Runtime | — | 运行库 | 栈帧/对象/GC 支撑程序运行 | 后勤 |

> CS143 的授课顺序几乎就是这个表：词法(2-5讲) → 语法(6-10讲) → 语义/类型(11-13讲) → 运行时/代码生成(14-17讲) → 优化(18-21讲) → 寄存器分配/GC(22-24讲)。

## 4. 一个贯穿全书的最小例子

我们用这个 Cool 程序（`tests/hello.cl`）在每篇结尾"追踪"它走到哪一步了：

```cool
class Main inherits IO {
  main() : Object {
    out_string("Hello, compiler!\n")
  }
};
```

**它穿过流水线时发生了什么：**

1. **词法**：`class Main inherits IO { ... }` → `CLASS TYPEID(Main) INHERITS TYPEID(IO) { ... }` 一串 Token。
2. **语法**：Token 流 → 一棵 AST（根是 `class Main`，里面一个 `main` 方法，方法体一个 dispatch 调用 `out_string(...)`）。
3. **语义**：检查 `Main` 确实继承了 `IO`、`out_string` 的实参确实是 `String`、`main` 返回值符合 `Object`。
4. **代码生成**：AST → LLVM IR（声明一个 `@main` 函数，里面 `call` 到运行时 `out_string`）。
5. **执行**：`lli` 跑 IR → 终端打印 `Hello, compiler!`。

后文每一篇都会回到这个例子。

## 5. 为什么学编译原理（对你，一个想做 PL / 深度学习编译器的人）

CS143 是公认的"神课"之一，但它的价值不在"你会写编译器"，而在它给你**一套分析程序的语言**。对你有三条直接价值：

1. **程序分析能力**：数据流分析（doc 10）是静态分析、形式验证、IDE 智能补全、安全审计的共同底座。
2. **性能工程能力**：vLLM 里你在优化 CUDA kernel、KV Cache——这些"算子融合、访存优化、图变换"正是 **TVM/XLA/MLIR 这类深度学习编译器**在做的事（doc 13 直接接上你的 CUDA 经验）。
3. **IR 设计能力**：LLVM IR（doc 07）和 MLIR（doc 13）是同一套"IR + pass"哲学的产物，理解前者是进入 PL 研究的门票。

**一句定心丸**：你有算法竞赛 + vllm + CUDA 的底子，这门课对你不会难，反而会把你散落的知识**串成一个体系**。
