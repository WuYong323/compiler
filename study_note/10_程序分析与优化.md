## 精炼段

代码生成后，IR 往往很"笨"（大量冗余的 load/store、死代码）。优化就是**语义保持的等价变换**，让程序更小/更快。局部优化（一个基本块内）简单；但程序有分支和循环，**值会跨基本块流动**，所以需要**全局优化**。数据流分析是全局优化的理论基础：把程序看成**控制流图（CFG）**，为每个基本块建立 `in/out` 方程（信息如何流入/流出），然后**迭代到不动点**。四种经典分析覆盖了"may/must × forward/backward"的矩阵：活跃变量、到达定值、可用表达式、常量传播。这套框架不仅是优化的底座，也是**编译器警告、IDE 智能提示、安全审计、TVM 的算子优化**的共同语言——对你做 PL/深度学习编译器至关重要。

---

## 1. 为什么需要优化：一个例子

我们的 codegen 直接生成的 IR 有很多冗余（比如每个 `let` 变量都 `alloca` + 反复 `load/store`）。LLVM 的优化能把：

```llvm
%x = alloca i32           ; 变量 x
store i32 3, i32* %x     ; x = 3
%a = load i32, i32* %x   ; 读 x
%b = add i32 %a, 1       ; x + 1
```

优化成：

```llvm
%b = add i32 3, 1        ; 常量传播：x 是常量 3，直接替换
; → 进一步：%b = 4（常量折叠）
```

**优化的两条铁律**：① **语义保持**（结果不变）② **只能更优**（不能更差）。

---

## 2. 局部优化 vs 全局优化

| | 局部（基本块内） | 全局（跨基本块） |
|---|---|---|
| 分析范围 | 单个基本块 | 整个 CFG |
| 例子 | 常量折叠、代数简化、窥孔优化 | 死代码消除、循环不变量外提 |
| 难度 | 简单 | 需要数据流分析 |

**局部优化例子**（都在一个基本块内）：
- **常量折叠**：`2 * 3` → `6`。
- **代数简化**：`x + 0` → `x`，`x * 1` → `x`。
- **公共子表达式消除**：`a = b+c; d = b+c` → `a = b+c; d = a`。

但**跨基本块**的优化（比如"这个变量在 if 的两条分支后还活着吗？""这个定义会不会到达这个使用点？"）必须分析**信息的流动**——这就是数据流分析。

---

## 3. 控制流图（CFG）与基本块

**控制流图** = 节点（基本块）+ 边（可能的跳转）。基本块是"只能从开头进、结尾出"的直线代码，结尾是 `br`/`ret` 等终结指令。

```
     ┌──────┐
     │ B0   │  x = 3
     └──┬───┘
        │ br (cond)
    ┌───┴───┐
    ▼       ▼
 ┌────┐  ┌────┐
 │ B1 │  │ B2 │
 └──┬─┘  └──┬─┘
    └───┬───┘
        ▼
     ┌────┐
     │ B3 │  use(x)
     └────┘
```

数据流分析的基本问题：**某个事实（如"x 的值是 3"）在程序的每一点是否成立？**

---

## 4. 数据流分析的统一框架

所有数据流分析都是同一个套路：为每个基本块 B 定义两个集合 **`in[B]`**（进入 B 时的事实）和 **`out[B]`**（离开 B 时的事实），满足方程：

```
in[B]  = meet( out[P] , 对所有前驱 P )
out[B] = transfer( in[B] )            （B 内部对事实的改变）
```

四个维度区分不同分析：

| 维度 | 选项 | 例子 |
|---|---|---|
| 方向 | forward / backward | 到达定值(前向) / 活跃变量(后向) |
| 合并 meet | ∪（may）/ ∩（must） | 到达定值(∪) / 可用表达式(∩) |
| 格（lattice） | 事实的取值空间 | 常量传播：⊤ 未知 / 具体值 / ⊥ 矛盾 |

**关键：这些方程是"联立"的**（in 依赖 out，out 依赖 in，块之间互相依赖），所以要用**不动点迭代**求解。

---

## 5. 活跃变量分析（Liveness）——最经典的例子

**问题**：变量 x 在基本块 B 出口是否"活跃"（它的值以后还会被用，且在再次定义前）？活跃变量信息用于**寄存器分配**（doc 11）和**死代码消除**。

**定义**（backward + may）：
- `use[B]`：B 中"在被定义前就被使用"的变量。
- `def[B]`：B 中"被定义"的变量。

**方程**（注意是**后向**：从后往前流）：

```
out[B] = ⋃ in[S] , 对所有后继 S
in[B]  = use[B] ∪ (out[B] - def[B])
```

**直觉**：`in[B]` = "在 B 里用到的变量" ∪ "离开 B 后还活着的变量中，B 没有重新定义的"。

**迭代算法**：初始化所有 `in/out = ∅`，反复代入方程直到所有集合不再变化（不动点）。单调递增 + 有限集合 → 一定收敛。

**例子**（上图 CFG）：
- `use[B3] = {x}`，`use[B1] = ∅, def[B1] = ∅`，`use[B0] = ∅, def[B0] = {x}`。
- 迭代后：`out[B0] = {x}`（x 在 B0 之后还活着），`in[B0] = ∅`；`out[B1] = {x}`, `out[B2] = {x}`, `in[B3] = {x}`。
- **结论**：x 在 B0 定义后、B3 使用前一直活跃 → 分配寄存器时 x 必须占一个寄存器。

---

## 6. 其他三种经典分析（一张表记住）

| 分析 | 方向 | may/must | 用途 |
|---|---|---|---|
| 活跃变量 Liveness | backward | may | 寄存器分配、死代码消除 |
| 到达定值 Reaching Defs | forward | may | 常量传播、判断某定义是否可达 |
| 可用表达式 Avail Exprs | forward | must | 公共子表达式消除 |
| 常量传播 Constant Prop | forward | must | 把变量替换成常量 |

**可用表达式**（must，forward）：`e = a+b` 在 B 入口是否"一定已经算过且 a、b 没被重新定义"？是的话就能复用结果，不用重算。

**常量传播**（must，forward，格是"未知⊤ / 具体常量 / 矛盾⊥"）：变量在某点是否恒为某常量？若是，直接替换。SSA 让这个分析特别简单（doc 07：每个变量只赋值一次，值唯一）。

---

## 7. 与现代工业的联系

- **LLVM 的 pass 体系**：`opt` 命令跑的就是一连串数据流分析。如 `opt -mem2reg`（把 alloca 提升为 SSA 寄存器）、`opt -dce`（死代码消除）、`opt -constprop`（常量传播）。你可以对我们生成的 IR 直接跑：`opt -O2 fact.ll -o fact_opt.ll`。
- **静态分析**：Clang 的 `-Wunused-variable`、`-Wuninitialized` 等警告，本质是数据流分析的变体。
- **深度学习编译器**：TVM 的算子融合、XLA 的图优化，虽然对象是"张量算子图"而非"基本块"，但**"信息在图上流动 + 不动点迭代"的思想完全同源**（doc 13 展开）。

> 学会数据流分析，你就掌握了"**分析任意程序性质**"的通用方法——这是 PL/编译研究最核心的能力。

## 8. 本文你掌握了什么 / 易错点 / 下一步

**掌握**：优化动机、局部 vs 全局、CFG、数据流方程（in/out/meet/transfer）、四维度、活跃变量的完整方程与迭代、四种经典分析、LLVM pass、与静态分析/TVM 的联系。

**易错点**：
1. **方向**：活跃变量是**后向**（out 由后继的 in 决定），别和 forward 搞混。
2. `in[B] = use[B] ∪ (out[B] - def[B])`——是"出去还活着**且没被 B 重新定义**"的变量，不是全部 out。
3. 迭代要**初始化**（liveness 初始 ∅；常量传播初始 ⊤），否则解错。
4. may 用 ∪、must 用 ∩。
