## 精炼段

编译器把程序翻译成机器代码后，程序要在内存里"活起来"。运行时组织就是设计**内存怎么用**：代码放哪、数据放哪、每次函数调用怎么在栈上开一个"栈帧"、对象在堆上怎么布局、方法调用怎么找到正确实现。核心四件事：① **栈帧**（局部变量/参数/返回地址的容器）② **调用约定**（调用双方如何传参、谁保存寄存器）③ **对象布局**（对象 = 类型标签 + 属性槽，偏移量固定）④ **分发表/vtable**（动态分派：对象携带指向方法表的指针，按固定下标查方法）。这些是 OO 语言编译的精髓，也是理解 C++/Java/Go 运行时的钥匙。

## 1. 内存布局：程序运行时的四块区域

```
高地址
┌─────────────┐
│   栈 Stack   │  ← 函数调用的栈帧，向下增长（后进先出）
├─────────────┤
│      ↓       │  （栈向下、堆向上，中间是空闲区）
│   空闲区     │
│      ↑       │
├─────────────┤
│   堆 Heap    │  ← 动态分配的对象（new），向上增长
├─────────────┤
│  数据 Data   │  ← 全局变量、字符串字面量
├─────────────┤
│  代码 Text   │  ← 机器指令（只读）
低地址
```

**直觉**：代码（Text）是"菜谱"，数据（Data）是"常备食材"，堆（Heap）是"现买现用的食材"，栈（Stack）是"做菜时临时摆放的盘子"。

---

## 2. 栈帧（Stack Frame / Activation Record）

**每次函数调用**都在栈上分配一块区域，叫**栈帧**，存这个函数**本次调用**的全部状态：

```
┌──────────────────────┐ 高地址（调用者帧）
│   调用者的栈帧         │
├──────────────────────┤
│ 实参（超出寄存器部分） │  ← 传给被调者的参数
│ 返回地址 return addr  │  ← 调用结束后回到哪
│ 保存的帧指针 old fp   │  ← 恢复调用者的帧
│ 局部变量 locals       │  ← 本函数的 let 变量、临时值
│ 溢出寄存器 spilled    │  ← 寄存器不够用时的备份
│ 给下一个调用的实参区  │  ← 本函数调用别人时传参用
├──────────────────────┤
│   栈顶（sp 向下）      │
└──────────────────────┘ 低地址
```

**两个关键寄存器**：
- **sp（栈指针）**：指向栈顶（最低地址）。
- **fp（帧指针）**：指向当前栈帧的固定位置，用于**稳定访问局部变量**（`fp - 8` = 第一个局部变量）。

**为什么用帧指针**：sp 会随压栈/弹栈移动，而 fp 在函数执行期间固定，所以局部变量都用 `fp + 固定偏移` 访问——简单可靠。

## 3. 调用约定（Calling Convention）

**问题**：函数 A 调用函数 B，参数怎么传？返回值怎么给？寄存器谁负责保存？

**约定**（以常见的 System V / x86-64 为例，思想通用）：

| 事项 | 约定 |
|---|---|
| 传参 | 前几个参数用**寄存器**（快），多余的压栈 |
| 返回值 | 放在指定寄存器（如 `rax`） |
| 调用者保存寄存器 | A 若要用，必须自己先存起来（B 可以随便破坏） |
| 被调用者保存寄存器 | B 若要用，必须自己先存、用完恢复（A 放心用） |
| 返回地址 | 由 `call` 指令压栈，`ret` 弹出 |

**直觉**：调用约定是"调用双方签的合同"——规定谁负责善后，避免 A、B 互相踩对方的寄存器。

> **重要**：因为我们的编译器**生成 LLVM IR**，这些栈帧/寄存器细节由 **LLVM 自动处理**（我们写 `call`、`alloca`，LLVM 负责分配寄存器和栈槽）。但**理解它们**仍然必要——否则你看不懂优化后的 IR，也无法 debug 性能问题。

## 4. 对象布局（Object Layout）——OO 语言的核心

**问题**：`class A { x:Int; y:String }` 的实例在内存里长什么样？

**标准答案**：对象 = **类型标签（tag）+ 属性槽（attributes）**：

```
A 的对象:
┌──────────────┐ offset 0
│  tag（类标签） │  ← 指向类 A 的元信息（名字、分发表…）
├──────────────┤ offset 8
│  x : Int      │
├──────────────┤ offset 16
│  y : String   │  ← 继承的属性排前面、自身属性排后面
└──────────────┘
```

**关键：偏移量在编译期固定**。属性 `x` 永远在 `offset 8`，所以 `obj.x` 编译成 `load [obj + 8]`（一条指令，O(1)）。

**继承时**：子类对象 = 父类的全部属性（**保持原偏移**）+ 自己的新属性（追加在后面）。

```
class B inherits A { z:Bool }
B 的对象:  tag | x | y | z   ← x、y 偏移不变，z 追加
```

**为什么继承的属性保持原偏移**：这样"把 B 当 A 用"时，`A` 的方法访问 `x`/`y` 用的偏移在 B 对象里依然有效——这是子类型多态的**内存基础**。

## 5. 分发表（Dispatch Table / vtable）——动态分派如何实现

**问题**：`l.head()` 里 `l` 的静态类型是 `List`，但运行时可能是 `Cons` 或 `Nil`。怎么找到正确的 `head` 实现？

**答案：分发表（vtable）**。每个类有一张**全局的方法指针表**，所有该类的实例通过 tag 共享它：

```
            List 的 vtable                Cons 的 vtable
         ┌───────────────┐            ┌───────────────┐
 idx 0   │ isNil -> List.isNil│        │ isNil -> Cons.isNil│ ← 重写：同一下标换函数
 idx 1   │ head -> List.head │        │ head -> Cons.head │
 idx 2   │ tail -> List.tail │        │ tail -> Cons.tail │
 idx 3   │        -        │        │ init -> Cons.init │ ← 新方法追加
         └───────────────┘            └───────────────┘

对象 → tag → 类元信息 → vtable → [method_index] → 函数指针 → 调用
```

**动态分派 = 三步**：
1. 从对象取出 tag；
2. 从 tag 取出 vtable；
3. 用**方法在 vtable 中的固定下标**取函数指针并调用。

**下标分配算法**（编译期完成，正是 doc 06 环境构建的自然延伸）：
- 遍历类层次（祖先优先）；
- 每个方法名分配一个**全局唯一的下标**；
- **重写的方法沿用父类的下标**（所以 `head` 在 List 和 Cons 里都是 idx 1）；
- 新方法分配新下标。

**静态分派**（`e@T.f`）则**跳过 vtable**，直接调 `T` 的方法——编译期就知道实现。

> 这就是 C++ 虚函数、Java 方法、Go 接口的底层机制。理解了它，就理解了"多态"到底花了几条指令、为什么虚函数调用比普通调用稍慢（多一次间接寻址）。

## 6. 我们的代码生成策略（承上启下，doc 09 执行）

因为目标后端是 **LLVM IR**，我们这样落地（doc 09 会逐条实现）：

| 概念 | 在 LLVM IR 里的落地 |
|---|---|
| 每个 Cool 对象 | 一个结构体 `{ i8* tag; <属性...> }`，用 `i8*`（或结构体指针）表示 |
| 类标签/tag | 指向全局常量"类描述符"（含类名字符串 + vtable 指针） |
| 分发表 | 全局常量数组 `[N x i8*]`（函数指针），按下标查 |
| 局部变量 | `alloca` 指令（LLVM 自动安排在栈帧） |
| 属性访问 | `getelementptr`（GEP）按偏移取字段 |
| 动态分派 | 取 tag → vtable → 按下标加载函数指针 → `call` |
| 静态分派 | 直接 `call` 目标类的函数 |
| Int/Bool/String | 特殊对象：`{tag, i32}`、`{tag, i1}`、`{tag, i32, i8*}`（长度+字符） |
| IO/字符串操作 | 调用外部运行时函数（`runtime.c`，见 doc 09） |

## 7. 本文你掌握了什么 / 易错点 / 下一步

**掌握**：内存四区、栈帧结构（sp/fp）、调用约定（谁保存寄存器）、对象布局（tag+属性、偏移固定）、继承保持偏移、vtable 与动态分派三步、下标分配算法、LLVM IR 里的落地方式。

**易错点**：
1. **继承的属性/方法必须保持原偏移/下标**——否则子类对象当父类用会访问错字段/调错方法。
2. 栈向**下**增长、堆向**上**增长（别记反）。
3. 动态分派比静态分派多**两次间接寻址**（tag→vtable→函数），这是虚调用开销的来源。
4. `caller-saved` vs `callee-saved` 寄存器：记"调用者保存 = 被调者可以随便破坏"。
