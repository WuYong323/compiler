## 精炼段

词法分析（lexing）是编译第一步：把一长串字符（`if x>3 then...`）切成有意义的**词元（Token）**，丢弃空白和注释，并记录每个 token 的行号供后续报错。它的理论支柱是**正则表达式 → NFA → DFA → 最小化**这条自动机流水线（flex 就是这么自动生成扫描器的）。我们**手写** lexer（现代工业编译器 Clang/Rust/Go 的主流做法），但要先吃透背后的自动机理论——因为它是所有"模式识别"问题的通用武器，也是 CS143 的必考内容。

---

## 1. 词法分析的任务与动机

**任务**：输入字符流，输出 Token 流。

```
输入:  "if x > 3 then x <- 1 fi"
输出:  IF  ID(x)  GT(>)  INT(3)  THEN  ID(x)  ASSIGN(<-)  INT(1)  FI
```

**为什么要单独做这一步**（而不是让语法分析器直接看字符）？三个理由：

1. **简化设计**：把"字符级琐碎问题"（空白、注释、大小写、字符串引号）和"结构级问题"（语法）分开。类比：翻译时先"分词"，再做"语法分析"，各自简单。
2. **效率**：识别 token 用**正则/自动机**（线性时间、可用 DFA 优化），比用 CFG 文法识别快得多。
3. **可移植**：不同平台的字符编码、行尾差异（`\n` vs `\r\n`）都在 lexer 层隔离。

### 1.1 三个核心术语（先分清）

| 术语 | 英文 | 含义 | Cool 例子 |
|---|---|---|---|
| 词元 | Token | 一个"词"的类别 + 属性（值、行号） | `IF`、`INT_CONST(3)`、`ID(x)` |
| 词素 | Lexeme | 源码里实际的字符片段 | `"if"`、`"3"`、`"x"` |
| 模式 | Pattern | 描述一类词素的规则 | 整数 = `[0-9]+` |

**直觉**：词素是"具体的人"，token 是"人的身份证信息"，模式是"什么算合法的人"。

## 2. 正则表达式（Regular Expressions）——token 的"模式语言"

> 正则表达式是描述**字符串集合**（语言）的形式语言。它只能表达**正则语言**，但恰好够描述 token。

### 2.1 定义（递归定义）

设字母表 Σ。正则表达式 R 描述一个语言 L(R)：

| 构造 | 记法 | 匹配的语言 |
|---|---|---|
| 空串 | ε | 只含空串 {ε} |
| 单字符 | `a` | {a} |
| 连接 | `ab` | L(a)·L(b) = 所有 "a 里的串拼 b 里的串" |
| 并/或 | `a\|b` | L(a) ∪ L(b) |
| 闭包 | `a*` | 0 个或多个 a 的串 |
| （非负闭包） | `a+` | 1 个或多个 a（= `aa*`） |
| （可选） | `a?` | 0 或 1 个 a（= `a\|ε`） |
| 字符类 | `[0-9]` | 0 到 9 任意一个 |
| （分组） | `(ab)*` | 优先级与分组 |

### 2.2 用正则写 Cool 的词法规则（01 篇规则的正则版）

| Token | 正则 | 说明 |
|---|---|---|
| TYPEID | `[A-Z][A-Za-z0-9_]*` | 大写开头 |
| OBJECTID | `[a-z][A-Za-z0-9_]*` | 小写开头 |
| INT_CONST | `[0-9]+` | 恒非负 |
| 空白 | `[ \t\n\f\r\v]+` | 6 种 |
| 行注释 | `--[^\n]*` | 到行尾 |
| 块注释 | `\(\*(([^*])|(\*+[^*)]))*\*\)` | 复杂，因为要嵌套（见下） |

> **注意**：块注释 `(* ... *)` 因**可嵌套**，**不是正则语言**（正则无法表达"配对括号"这类结构）！所以 flex 用正则**只能识别单层**注释，嵌套要靠额外的计数器。这就是为什么我们手写 lexer 时用**深度计数器**处理注释（见 §5.4）。这是"正则表达式的表达能力边界"的经典例子。

### 2.3 正则的等价变换（做题/写 flex 常用）

- 交换律/结合律/分配律等（德摩根式的代数），这里不展开，核心记住：**正则、NFA、DFA 三者表达的语言完全等价**（正则语言）。

## 3. 有限自动机（Finite Automata）——token 的"识别机器"

### 3.1 NFA 与 DFA（先直觉）

- **DFA（确定性）**：每个状态 + 每个输入字符，**最多一条**转移；无 ε 转移。识别快（每字符 O(1)）。
- **NFA（非确定性）**：一个状态对同一字符可有多条转移，或 ε 转移（不读输入就跳）。**表达简洁、易构造**，但模拟时可能要"猜"。

**直觉**：NFA 像"有多条岔路的地图"（你要猜走哪条），DFA 像"每步都唯一的导航"（不用猜）。二者识别能力相同，只是 DFA 状态可能更多。

### 3.2 从正则到 NFA：Thompson 构造（归纳构造，核心算法）

对正则的每个构造，机械地拼出对应 NFA（每个 NFA 恰有一个开始态、一个接受态）：

```
   ε:      (s) --ε--> (f)
   a:      (s) --a--> (f)
   R1R2:   (s1)-->[R1]--ε--> (s2)-->[R2] -->(f)
   R1|R2:        ┌─>[R1]─┐
            (s)--ε        ε-->(f)
                 └─>[R2]─┘
   R*:     (s)--ε-->[R]--ε-->(f)
            ↑            ↓
            └────ε───────┘        (闭包的回边)
```

这就是 flex 生成扫描器背后的第一步。**理解它 = 理解"正则怎么变成机器"**。

### 3.3 从 NFA 到 DFA：子集构造（消除不确定性）

核心思想：**一次追踪 NFA 所有可能状态**。DFA 的每个状态 = NFA 状态的一个**集合**。

```
ε-closure(S)   = S 及所有"只经 ε 边可达"的状态
move(T, a)     = 从 T 中状态经字符 a 能到达的状态集合

算法：
  T0 = ε-closure({nfa_start})
  对每个 DFA 状态 T 和每个字符 a：
     U = ε-closure(move(T, a))
     if U 非空：加 DFA 转移 T --a--> U（U 若是新集合，加入待处理队列）
  DFA 的接受态 = 含 NFA 接受态的状态集合
```

结果：DFA 状态数最坏可达 2^N（N = NFA 状态数），但实际语言（如 token）通常远小于此。

### 3.4 DFA 最小化（状态合并，压缩扫描器）

把"行为完全相同的状态"合并，得到最小 DFA。核心是**划分算法**：
1. 初始把所有状态分成两组：接受态 / 非接受态。
2. 反复：若同组内两个状态对某字符转移到**不同组**，就拆开它们。
3. 直到不能再拆。每组合并为一个状态。

> 最小化后的 DFA 是**唯一**的（同构意义下），状态数最少，扫描最快。

### 3.5 这一节的意义（诚实说清楚）

我们**手写 lexer 不会真的去建 DFA 表**——手写就是把"识别逻辑"直接写成 C++ 代码。但你**必须懂这套理论**，因为：
1. 它是 CS143 的考试重点，也是 PL 研究的基本功；
2. `flex`（CS143 原课的 PA1 工具）就是把这套流水线自动化的；
3. 它是"正则 → 自动机"思想的典型应用，后面"数据流分析（doc 10）"也是"不动点迭代"，思想同源。

## 4. 手写 lexer vs 自动生成（flex）——工业界的真实选择

| | 手写 lexer | flex 生成 |
|---|---|---|
| 方式 | 直接写识别逻辑 | 用正则写规则，flex 生成 C 扫描器 |
| 可读/可调试 | 高，逻辑直白 | 低，生成代码是一大堆 DFA 表 |
| 灵活度 | 高（注释嵌套、错误恢复随便写） | 受正则表达力限制（嵌套注释要 hack） |
| 依赖 | 无 | 需要 flex 工具链 |
| 工业代表 | **Clang、Rust、Go、v8、Swift** | gcc、早期工具 |

**结论**：现代工业编译器几乎**都手写** lexer（因为错误诊断、性能、可读性）。我们跟随工业主流**手写**，同时把 flex 的等价写法作为参考放在文末（对应 CS143 的 PA1）。

## 5. 我们的 lexer 设计（把 01 篇的规则变成代码）

### 5.1 Token 的定义（`token.h`）

每个 Token 有：**类别**（kind）、**词素**（lexeme）、**行号/列号**（用于报错）。

Token 类别分 4 组：
- **关键字**：`CLASS ELSE FI IF IN INHERITS ISVOID LET LOOP POOL THEN WHILE CASE ESAC NEW OF NOT TRUE FALSE`
- **标识符/字面量**：`TYPEID OBJECTID INT_CONST STR_CONST`
- **标点/运算符**：`{ } ( ) : ; , <- . @ ~ + - * / <= < = =>`
- **元 token**：`END`（文件结束）、`ERROR`（错误，词素 = 错误信息）

### 5.2 识别优先级（lexer 的主循环，`next()`）

```
skip 空白和注释
if 到文件尾 → 返回 END
if 字母开头   → 读标识符/关键字
if 数字开头   → 读整数（查范围）
if '"' 开头   → 读字符串（查转义/长度/非法字符）
else          → 读运算符/标点（多字符 <- <= => 优先）
其它          → ERROR（非法字符）
```

### 5.3 关键字的大小写规则（实现要点）

关键在 `keywordKind()`：对读到的标识符，**转小写后查关键字表**；但 `true`/`false` 额外要求**首字符是小写**（否则按 TYPEID 处理，见 01 篇 §3.3）。例：`IF`、`iF` → `IF`；`True`、`FALSE` → TYPEID。

### 5.4 字符串与注释（两个"状态机"，最易错）

- **字符串**：读 `"` 后循环——遇 `\` 就"吃掉"下一个字符（连同 `\` 一起存，**不翻译**）；裸 `"` 结束；遇 `\n`/EOF/NUL → 报错；长度 >1024 → 报错。
- **块注释**：`(*` 开、`*)` 闭，用**深度计数器**支持嵌套；EOF 时深度未归零 → 报错。

> 这就是 §2.2 说的"正则表达不了嵌套"——手写一个 `depth++/depth--` 就轻松解决。

### 5.5 错误处理

Lexer 遇错时返回一个 `ERROR` token，词素存错误信息、记录行号。驱动程序打印 `ERROR: line N: message` 并停止。**更完善的错误恢复（跳过坏 token 继续）留到后面 parser 一起讲**，因为它涉及"如何在出错后重新同步"，属于语义/语法阶段的话题。

### 6.2 `src/lexer.h`

```cpp
#pragma once
#include <string>
#include <utility>
#include "token.h"

namespace cool {

class Lexer {
public:
  // 按值持有源码（move），避免持有 ss.str() 临时对象的悬垂引用
  explicit Lexer(std::string src) : src_(std::move(src)) {
    // 跳过 UTF-8 BOM（EF BB BF）：部分编辑器/工具会在文件头写入
    if (src_.size() >= 3 && (unsigned char)src_[0] == 0xEF &&
        (unsigned char)src_[1] == 0xBB && (unsigned char)src_[2] == 0xBF) {
      pos_ = 3;
    }
  }
  Token next();                 // 返回下一个 token（EOF 时为 END）

private:
  std::string src_;
  size_t pos_ = 0;
  int line_ = 1;
  int col_ = 1;
  std::string error_;           // 待报错误（非空表示有错）

  bool atEnd() const { return pos_ >= src_.size(); }
  char peek() const { return atEnd() ? '\0' : src_[pos_]; }
  char peek2() const { return pos_ + 1 >= src_.size() ? '\0' : src_[pos_ + 1]; }
  char advance();               // 消费一个字符，维护行/列

  void skipWhitespaceAndComments();
  Token readIdentifier();
  Token readNumber();
  Token readString();
  Token readOperator();
};

} // namespace cool
```

### 6.3 `src/lexer.cpp`

```cpp
#include "lexer.h"
#include <cctype>

namespace cool {

char Lexer::advance() {
  if (atEnd()) return '\0';
  char c = src_[pos_++];
  if (c == '\n') { ++line_; col_ = 1; } else { ++col_; }
  return c;
}

// 跳过空白与两种注释；发现未闭合注释时设置 error_
void Lexer::skipWhitespaceAndComments() {
  while (true) {
    while (!atEnd() && std::isspace((unsigned char)peek())) advance();
    if (atEnd()) return;
    // 行注释 "--"
    if (peek() == '-' && peek2() == '-') {
      advance(); advance();
      while (!atEnd() && peek() != '\n') advance();
      continue;
    }
    // 块注释 "(* ... *)"，可嵌套
    if (peek() == '(' && peek2() == '*') {
      int depth = 0;
      while (!atEnd()) {
        if (peek() == '(' && peek2() == '*') { advance(); advance(); ++depth; }
        else if (peek() == '*' && peek2() == ')') {
          advance(); advance(); --depth;
          if (depth == 0) break;
        }
        else advance();
      }
      if (depth != 0) { error_ = "EOF in comment"; return; }
      continue;
    }
    return; // 下一个 token 的起始位置
  }
}

// 关键字判定（大小写不敏感；true/false 首字符必须小写）
static bool keywordKind(const std::string& s, Tok& out) {
  std::string low; low.reserve(s.size());
  for (char c : s) low.push_back((char)std::tolower((unsigned char)c));
  if (low == "true")  { if (s[0] == 't') { out = Tok::TRUE;  return true; } return false; }
  if (low == "false") { if (s[0] == 'f') { out = Tok::FALSE; return true; } return false; }
  static const std::pair<const char*, Tok> kws[] = {
    {"class", Tok::CLASS}, {"else", Tok::ELSE}, {"fi", Tok::FI}, {"if", Tok::IF},
    {"in", Tok::IN}, {"inherits", Tok::INHERITS}, {"isvoid", Tok::ISVOID},
    {"let", Tok::LET}, {"loop", Tok::LOOP}, {"pool", Tok::POOL}, {"then", Tok::THEN},
    {"while", Tok::WHILE}, {"case", Tok::CASE}, {"esac", Tok::ESAC},
    {"new", Tok::NEW}, {"of", Tok::OF}, {"not", Tok::NOT},
  };
  for (auto& kw : kws)
    if (low == kw.first) { out = kw.second; return true; }
  return false;
}

Token Lexer::readIdentifier() {
  int sl = line_, sc = col_;
  std::string s; s += advance();
  while (!atEnd() && (std::isalnum((unsigned char)peek()) || peek() == '_')) s += advance();
  Tok k;
  if (keywordKind(s, k)) return {k, s, sl, sc};
  if (std::isupper((unsigned char)s[0])) return {Tok::TYPEID, s, sl, sc};
  return {Tok::OBJECTID, s, sl, sc};
}

Token Lexer::readNumber() {
  int sl = line_, sc = col_;
  std::string s;
  while (!atEnd() && std::isdigit((unsigned char)peek())) s += advance();
  // 32 位有符号非负上限 2147483647：先比长度，再比字典序
  if (s.size() > 10 || (s.size() == 10 && s > "2147483647")) {
    error_ = "Integer constant too large";
    return {Tok::ERROR, s, sl, sc};
  }
  return {Tok::INT_CONST, s, sl, sc};
}

Token Lexer::readString() {
  int sl = line_, sc = col_;
  advance(); // 消费开头的 "
  std::string val;
  while (true) {
    if (atEnd()) { error_ = "EOF in string constant"; return {Tok::ERROR, val, sl, sc}; }
    char c = advance();
    if (c == '"') break;                       // 正常结束
    if (c == '\n') { error_ = "Unterminated string constant"; return {Tok::ERROR, val, sl, sc}; }
    if (c == '\0') { error_ = "String contains NUL character"; return {Tok::ERROR, val, sl, sc}; }
    if (c == '\\') {                           // 反斜杠：吃掉下一个字符，两个字面都保留
      if (atEnd()) { error_ = "EOF in string constant"; return {Tok::ERROR, val, sl, sc}; }
      char d = advance();
      if (d == '\n') { error_ = "Unterminated string constant"; return {Tok::ERROR, val, sl, sc}; }
      val += c; val += d;                      // \t \n 也不翻译，交给运行时
      continue;
    }
    val += c;
  }
  if (val.size() > 1024) { error_ = "String constant too long"; return {Tok::ERROR, val, sl, sc}; }
  return {Tok::STR_CONST, val, sl, sc};
}

Token Lexer::readOperator() {
  int sl = line_, sc = col_;
  char c = advance();
  switch (c) {
    case '{': return {Tok::LBRACE, "{", sl, sc};
    case '}': return {Tok::RBRACE, "}", sl, sc};
    case '(': return {Tok::LPAREN, "(", sl, sc};
    case ')': return {Tok::RPAREN, ")", sl, sc};
    case ':': return {Tok::COLON, ":", sl, sc};
    case ';': return {Tok::SEMI, ";", sl, sc};
    case ',': return {Tok::COMMA, ",", sl, sc};
    case '.': return {Tok::DOT, ".", sl, sc};
    case '@': return {Tok::AT, "@", sl, sc};
    case '~': return {Tok::TILDE, "~", sl, sc};
    case '+': return {Tok::PLUS, "+", sl, sc};
    case '-': return {Tok::MINUS, "-", sl, sc};
    case '*': return {Tok::STAR, "*", sl, sc};
    case '/': return {Tok::SLASH, "/", sl, sc};
    case '<':
      if (peek() == '-') { advance(); return {Tok::ASSIGN, "<-", sl, sc}; }
      if (peek() == '=') { advance(); return {Tok::LE, "<=", sl, sc}; }
      return {Tok::LT, "<", sl, sc};
    case '=':
      if (peek() == '>') { advance(); return {Tok::DARROW, "=>", sl, sc}; }
      return {Tok::EQ, "=", sl, sc};
    default:
      error_ = std::string("Unrecognized character '") + c + "'";
      return {Tok::ERROR, std::string(1, c), sl, sc};
  }
}

Token Lexer::next() {
  skipWhitespaceAndComments();
  if (!error_.empty()) {
    Token t{Tok::ERROR, error_, line_, col_};
    error_.clear();
    return t;
  }
  if (atEnd()) return {Tok::END, "", line_, col_};
  char c = peek();
  if (std::isalpha((unsigned char)c)) return readIdentifier();
  if (std::isdigit((unsigned char)c)) return readNumber();
  if (c == '"') return readString();
  return readOperator();
}

} // namespace cool
```

### 6.4 `src/main.cpp`（本阶段：词法驱动，后续扩展成完整管线）

```cpp
#include <fstream>
#include <iostream>
#include <sstream>
#include "lexer.h"
using namespace cool;

int main(int argc, char** argv) {
  if (argc < 2) { std::cerr << "usage: coolc <file.cl>\n"; return 2; }
  std::ifstream in(argv[1]);
  if (!in) { std::cerr << "cannot open: " << argv[1] << "\n"; return 2; }
  std::stringstream ss; ss << in.rdbuf();
  Lexer lex(ss.str());

  bool hadError = false;
  for (;;) {
    Token t = lex.next();
    if (t.kind == Tok::END) break;
    if (t.kind == Tok::ERROR) {
      std::cerr << "ERROR: line " << t.line << ": " << t.lexeme << "\n";
      hadError = true;
      break;               // 本阶段遇错即停；错误恢复在 doc 03/05 完善
    }
    std::cout << "line " << t.line << ": " << tokName(t.kind)
              << "  '" << t.lexeme << "'\n";
  }
  return hadError ? 1 : 0;
}
```

## 8. 附录：CS143 原课的 flex 写法（PA1 参考）

CS143 原课 PA1 用 flex 写 lexer。等价逻辑（节选，**仅供对照**，我们的主编译器不依赖它）：

```lex
/* cool.l 节选 */
DIGIT    [0-9]
%%
 /* 关键字（flex 的"最长匹配优先"，关键字先于标识符） */
(?i:class)      { return (CLASS); }
(?i:inherits)   { return (INHERITS); }
...
t(?i:rue)       { return (BOOL_CONST); }   /* true/false 首字母必须小写 */
f(?i:alse)      { return (BOOL_CONST); }

 /* 标识符 */
[A-Z][A-Za-z0-9_]* { return (TYPEID); }
[a-z][A-Za-z0-9_]* { return (OBJECTID); }

 /* 字符串（Cool 特色：\ 吃掉下一字符，不翻译） */
\"(\\.|[^"\\\n])*\" { /* 校验长度/内容后返回 STR_CONST */ }

 /* 注释（嵌套靠 flex 的 start condition + 计数） */
<COMMENT>\(\*      { comment_depth++; }
<COMMENT>\*\)      { comment_depth--; if (comment_depth==0) BEGIN(INITIAL); }
%%
```

> flex 里 `(?i:...)` 表示大小写不敏感；`t(?i:rue)` 表示"首字符 `t` 必须小写、其余不敏感"——与我们的 `keywordKind` 完全对应。

## 9. 本文你掌握了什么 / 易错点 / 下一步

**掌握**：token/lexeme/pattern 三概念、正则表达式、NFA/DFA、Thompson 构造、子集构造、DFA 最小化、手写 vs flex 的取舍、手写 lexer 的完整实现。

**易错点**：
1. 块注释 `(* *)` **可嵌套** → 必须用深度计数器，不能只用正则。
2. 字符串里 `\t` `\n` **不翻译**（是两个字面字符）；`\"` 不变成 `"`。
3. 整数**恒非负**，上限 2147483647，越界是**词法错误**。
4. 关键字大小写不敏感，但 `true`/`false` 首字符必须小写。
5. 字符串字面量长度上限 1024；含裸换行/EOF/NUL 都是错误。
6. **C++ 陷阱（实测踩坑）**：Lexer 要**按值持有源码**（`std::string src_`），不要写 `const std::string& src_` 去绑定 `ss.str()` 的临时对象——临时对象在构造函数语句结束后就析构，引用悬垂，之后读到的是已释放内存（表现为随机乱码）。
7. 建议 lexer 开头跳过 UTF-8 BOM（`EF BB BF`），兼容带 BOM 的编辑器/工具。
