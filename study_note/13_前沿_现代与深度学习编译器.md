## 精炼段

学完 CS143，你已经掌握了编译器这门手艺的**全部内核**：词法/语法/语义、IR、SSA、数据流分析、寄存器分配、运行时。现代工业编译器只是把这些概念**放大、硬化、针对领域定制**。本讲把散落的知识接成一张地图：**JIT** 把编译从"提前"变成"运行时"；**LLVM/Clang** 是通用编译器的集大成者；**MLIR** 把"单一 IR"泛化成"多级可定制 IR（Dialect）"；**TVM/XLA/Triton** 则是深度学习编译器——它们编译的对象从"程序"变成"张量算子图"，但用的还是 IR + pass + 数据流分析 + 代码生成。对要做 PL/深度学习编译器科研的你，这篇是"从课程到前沿"的桥。

## 1. 一张总表：CS143 概念 → 工业系统

| CS143 概念 | LLVM/Clang | MLIR | TVM / XLA | JIT（V8/PyTorch） |
|---|---|---|---|---|
| 词法/语法分析 | Clang 前端（手写递归下降） | 各自前端 | 图前端（relay/前端导入） | JS parser / TorchScript |
| 中间表示 IR | LLVM IR（SSA） | 多层 IR（Dialect） | Relay（图 IR）+ TIR（张量 IR） | 字节码 + 热函数 IR |
| 优化 pass | `opt -O2`（数据流分析） | 逐级 lowering | 算子融合、图改写、自动调优 | 运行时 profile 引导优化 |
| 代码生成 | `llc` → 机器码 | 降到 LLVM/自定义后端 | 生成 CUDA/OpenCL 代码 | 生成机器码（JIT） |
| 寄存器分配 | greedy 分配器 | — | GPU 寄存器分配 | 线性扫描 |

## 2. JIT（即时编译）：把编译从"提前"变"运行时"

**AOT（提前编译）**：程序跑之前就编译完（我们的 coolc）。
**JIT（即时编译）**：**运行时**边执行边编译热点代码。

**流程**（以 V8 为例）：
```
JS 源码 → 字节码（解释执行，启动快）
              │
         profile 找到"热函数"
              │
         JIT 编译成机器码（越热优化越狠）
```

**核心权衡**：JIT 花编译时间换执行时间，所以**只编译热点**；且能利用**运行时信息**（类型、分支走向）做 AOT 做不到的优化。PyTorch 的 `torch.compile`、Java 的 HotSpot、JS 的 V8 都是 JIT。

**为什么和你有关**：vLLM 里跑的是编译好的 kernel；但 PyTorch 2.x 的 `torch.compile` + `Inductor` 就是一套 **JIT 深度学习编译器**——运行时把你的模型图编译成 Triton/CUDA kernel。

## 3. LLVM / Clang：通用编译器的集大成者

**LLVM** = "一个可复用的编译器基础设施"：提供 IR（LLVM IR）、优化 pass、代码生成、JIT 引擎。

**Clang** = 用 LLVM 的 C/C++/ObjC 前端。分工清晰对应 CS143 的三段式：

```
Clang 前端（词法/语法/语义 → LLVM IR）
   ↓
LLVM 中端（opt：数据流分析优化 IR）
   ↓
LLVM 后端（llc：指令选择 → 寄存器分配 → 机器码）
```

**关键认知**：我们手写编译器时，"IR 就是文本、pass 要自己写"；LLVM 把这套东西做成了**库**（C++ API），Rust、Swift、Julia 等几十种语言都借它的中后端。**你学 CS143 时手写的一切，就是 LLVM 内部在做的事**。

---

## 4. MLIR：把"单一 IR"泛化成"多级可定制 IR"

LLVM IR 是**单层**的（偏底层）。深度学习编译器需要**多层抽象**：从"高层算子图"到"张量级"到"循环级"到"硬件指令"，每层都做优化。MLIR 的答案是 **Dialect**：

```
一个 Dialect = 自定义的"一套 IR 指令 + 类型 + 语义"（例如 tensor、linalg、gpu、llvm）
程序从高层 Dialect 逐级 lowering 到底层 Dialect，每层用 pass 优化
```

**关键思想**：MLIR 把 LLVM 的"IR + pass"哲学**参数化**了——你不必为每个领域发明一套新编译器，只要定义新 Dialect。TensorFlow 的 XLA、TPU 编译器、以及很多 AI 芯片工具链都构建在 MLIR 上。

> 对科研方向：MLIR 是当前 PL + 深度学习编译器交叉领域**最重要的基础设施**之一。理解了 doc 07 的 SSA/IR 和 doc 10 的 pass/数据流分析，MLIR 的概念就水到渠成。

## 5. 深度学习编译器：TVM / XLA / Triton

深度学习框架（PyTorch/TF）里的算子要跑在 GPU/TPU/NPU 上，需要**图级 + 算子级**两层编译：

| 系统 | 图级 IR | 算子级 | 特色 |
|---|---|---|---|
| **TVM** | Relay（图 IR，做算子融合/图改写） | TIR（张量 IR，做循环变换） | **自动调优（AutoTVM/Ansor）**：搜索最优实现 |
| **XLA** | HLO（High-Level Optimizer） | 后接 LLVM/GPU 后端 | 把 TF/JAX 图编译到加速器 |
| **Triton** | — | Python 写 block 级 kernel，编译器生成 GPU 代码 | OpenAI 出品，PyTorch 2.0 的 Inductor 后端 |

**它们的编译原理 = CS143 的编译原理**，只是对象从"语句"换成"张量算子"：
- **算子融合（operator fusion）** = 把 `relu(matmul(x,w)+b)` 融成一个 kernel，避免中间张量来回读写显存——这就是**数据流图优化**（doc 10 思想）。
- **循环变换（tiling/unrolling/vectorization）** = 针对内存层次（你 CUDA 里的 shared memory、register tiling）的"代码生成优化"。
- **自动调优（autotuning）** = 把"选哪个 tiling 参数"变成一个**搜索问题**（Ansor 用进化搜索 + cost model）。

> 这正是你 CUDA + vllm 经验能直接发力的地方：**你手写过 kernel、调过 occupancy、优化过访存，现在加上编译原理的视角，就能理解 TVM/XLA 在"自动"做什么。**

## 6. 一条建议的学习路径（你：想走 PL / 深度学习编译器科研）

1. **吃透本套 CS143 笔记 + 跑通 coolc**（已基本完成）——这是地基。
2. **LLVM 进阶**：读《LLVM Essentials》/官方 Kaleidoscope 教程，用 LLVM C++ API 把 coolc 的后端换成 LLVM API（对比你手写的文本 IR）。
3. **MLIR 入门**：官方 Toy tutorial（用 MLIR 写一个小语言），理解 Dialect + lowering。
4. **深度学习编译器**：读 [TVM 论文](https://arxiv.org/abs/1802.04799) 和 [MLIR 论文](https://arxiv.org/abs/2002.11054)，结合你的 CUDA 背景动手跑 TVM 的算子调度。
5. **深入一个方向**：算子自动调优（Ansor）、图优化、内存规划、或某类 AI 芯片的编译栈。

## 7. 本文你掌握了什么 / 易错点 / 下一步

**掌握**：AOT vs JIT、LLVM/Clang 三段式、MLIR 的 Dialect/多级 IR、TVM（Relay/TIR）、XLA（HLO）、Triton、算子融合/自动调优、CS143→工业的映射、你的学习路径。

**易错点**：
1. JIT ≠ 解释器：JIT 是**编译**（生成机器码），只是时机在运行时。
2. MLIR 不是"又一个 IR"，是"**定义 IR 的框架**"（Dialect 可定制）。
3. 深度学习编译器的"优化"重点不是寄存器分配，而是**算子融合 + 内存层次优化 + 自动调优**。
