## 精炼段

这是编译器流水线的最后一环（CP4）：把带类型的 AST 翻译成 LLVM IR。我们的**核心设计**是"**一切皆 `i8*`**"——所有 Cool 值（Int/Bool/String/对象）都是指向堆对象的指针，`isvoid` 就是判空。对象布局沿用 doc 08 的 `{tag, 属性...}`，动态分派走 `tag → class_meta → vtable → 函数指针`。整数/布尔运算先**拆箱**（`bitcast` + `getelementptr` + `load`）、算完再**装箱**（`cool_alloc` + `store`）。内建方法（`abort/type_name/copy`、IO、String）写成 IR 函数，配合一个 40 行的 `runtime.c`（malloc/printf/字符串工具）。学完本篇，你就有了一条**完整可运行**的 Cool → LLVM IR 编译流水线。

## 1. 代码生成的任务与我们的表示选择

**输入**：带类型 AST（typechecker 已在每个 `Expr` 上标注 `type`）。
**输出**：LLVM IR 文本（一个 Module）。

**关键设计决策——值如何表示？** 我们选**装箱（boxed）+ 统一指针**：

| Cool 值 | LLVM 表示 |
|---|---|
| 任何值 | `i8*`（指向堆对象的指针） |
| Int 对象 | `%Int = type { i8*, i32 }`（tag + 值） |
| Bool 对象 | `%Bool = type { i8*, i32 }`（tag + 0/1） |
| String 对象 | `%String = type { i8*, i32, i8* }`（tag + 长度 + 字符指针） |
| 用户类 C 对象 | `%C = type { i8*, i8*, ... }`（tag + 各属性指针） |
| void | `null` |

**为什么装箱**：Cool 语义是"一切皆对象"（Int 也是对象、也有 `type_name()` 等方法），装箱让"把 Int 传给 `Object` 形参"这类场景天然正确——所有值都是指针，无需标记。

> 真实编译器（如 C++）通常对 Int 用**不装箱**表示（更快），代价是要处理"基本类型 vs 对象"的统一问题。教学上装箱更简单、更忠实。

## 2. 对象布局与分发表（doc 08 蓝图 → IR 落地）

### 2.1 类描述符（class meta）

每个类一个全局常量，供对象 tag 指向：

```llvm
%class_meta_t = type { i8*, i8**, i32, i32 }   ; {类名字符串, vtable指针, 对象字节数, 类ID}

@class_Cons = constant %class_meta_t {
  i8* <指向 "Cons" 的字符串>,
  i8** bitcast ([16 x i8*]* @vtable_Cons to i8**),
  i32 24,       ; Cons 大小 = (1 + 2 属性) * 8
  i32 7         ; 类 ID（case 分派用）
}
```

### 2.2 分发表（vtable）

每个类一张全局函数指针表，**重写沿用父类下标、新方法追加新下标**（doc 08 的算法）：

```llvm
@vtable_List = [ ... , @List.tail, @List.isNil, @List.head, ... ]
@vtable_Cons = [ ... , @Cons.tail, @Cons.isNil, @Cons.head, @Cons.init, ... ]
                    ↑ 下标 10    ↑ 11        ↑ 12        ↑ 13 新增
```

### 2.3 动态分派（三段间接寻址）

`l.isNil()` 编译成：

```llvm
%tag  = load i8*, i8** %l                  ; 对象 offset 0 是 tag
%meta = bitcast i8* %tag to %class_meta_t*
%vt   = load i8**, i8*** <meta 的 vtable 字段>   ; 取 vtable 指针
%fnp  = load i8*, i8** <vtable + 下标 11>       ; 按下标取函数指针
%fn   = bitcast i8* %fnp to i8* (i8*, i8*)*
%r    = call i8* %fn(i8* %l)               ; 调用（传 self 为第一实参）
```

**静态分派**（`e@T.f`）则直接 `call @T.f(...)`，跳过 vtable。

## 3. 逐语法翻译（本阶段的完整代码）

> 完整实现在 `src/codegen.cpp`。下面是核心片段（`result_` = 当前表达式产生的 `i8*` 值）。

### 3.1 整数/布尔/字符串字面量 → 全局常量

```cpp
void CodeGen::visit(const IntConst& e) { result_ = intConst(e.value); }
// intConst: 惰性生成 @int_5 = constant %Int { tag, i32 5 }（去重、放模块级）
```

### 3.2 算术：拆箱 → 算 → 装箱

```cpp
void CodeGen::visit(const Binary& e) {   // + - * /
  std::string a = unboxInt(codegenExpr(*e.lhs));   // i8* -> i32
  std::string b = unboxInt(codegenExpr(*e.rhs));
  std::string r = fresh(); emit(r + " = add i32 " + a + ", " + b);
  result_ = boxInt(r);                              // i32 -> i8*（新 Int 对象）
}
```

`unboxInt` = `bitcast i8* → %Int*` + `getelementptr` 字段 1 + `load i32`；`boxInt` = `cool_alloc(16)` + 存 tag + 存值。

### 3.3 if：用 phi 合并两分支

```cpp
std::string ci = unboxBool(codegenExpr(*e.cond));
emit(b + " = icmp ne i32 " + ci + ", 0");
emit("br i1 " + b + ", label %then, label %else");
emit("then:");  std::string tv = codegenExpr(*e.then_);  emit("br label %end");
emit("else:");  std::string ev = codegenExpr(*e.else_);  emit("br label %end");
emit("end:");
emit(phi + " = phi i8* [ " + tv + ", %then ], [ " + ev + ", %else ]");  // SSA 合并
```

### 3.4 let：局部变量用 alloca（LLVM 自动管栈帧）

```cpp
void CodeGen::visit(const Let& e) {
  scopes_.push_back({});
  for (auto& b : e.bindings) {
    std::string slot = fresh(); emit(slot + " = alloca i8*");
    emit("store i8* " + (b.init ? codegenExpr(*b.init) : defaultFor(b.type)) + ", i8** " + slot);
    scopes_.back()[b.name] = slot;
  }
  result_ = codegenExpr(*e.body);
  scopes_.pop_back();
}
```

### 3.5 new：分配 + 存 tag + 逐属性初始化（doc 08 的"继承序初始化"）

```cpp
std::string CodeGen::allocateAndInit(const std::string& cls) {
  obj = call @cool_alloc(sizeOf(cls)); bitcast to %cls*; store tag;
  // 在 self = 新对象 的作用域内，按 attrs_ 顺序初始化（继承的属性在前）
  for (auto& slot : attrs_.at(cls))
     val = slot.init ? codegenExpr(*slot.init) : defaultFor(slot.type);
     store val 到字段 off+1;
}
```

### 3.6 case：按运行时类 ID 分派（编译期展开后代集合）

```cpp
// scrutinee 的 tag → meta → 类 ID
// 对每个分支类型 T，其匹配集 = descendants(T)（T 及其所有子类）
// 生成: id == ID(T1) || id == ID(T2) || ...  →  跳分支体
// 分支体: 把 scrutinee 绑给分支变量，求值 body；无匹配 → cool_abort()
```

### 3.7 属性访问/赋值（`self` + GEP 固定偏移）

```cpp
// 属性读 obj.x：load self → bitcast → getelementptr 字段(off+1) → load
// 属性写 obj.x <- e：同上 → store
// 局部变量：scope 栈里 name → alloca，load/store
```

## 4. 内建方法（写成 IR 函数）

`Object.abort/type_name/copy`、`IO.out_string/out_int/in_string/in_int`、`String.length/concat/substr` 都作为 IR 函数 emit（见 `emitBuiltinMethods`），它们调用 `runtime.c` 提供的 C 函数：

| runtime.c 函数 | 作用 |
|---|---|
| `cool_alloc/cool_copy` | malloc / malloc+memcpy（copy 用） |
| `print_int/print_str` | 打印（`print_str` 把 `\t`→tab、`\n`→换行） |
| `read_int/read_str` | 输入 |
| `str_len/str_concat/str_substr/str_cmp` | 字符串工具 |

**实测命令**（Windows + MSYS2 ucrt64，LLVM 21.1.8）：

```bash
g++ -std=c++17 -o coolc.exe src/*.cpp
./coolc.exe tests/factorial.cl -o factorial.ll
llvm-as factorial.ll -o factorial.bc      # IR 语法合法（exit 0）

./factorial.exe                            # 输出 120
```

**IR 结构验证**：
- `@vtable_Cons` 的 `tail/isNil/head` 与 `@vtable_List` **同下标**、`init` 追加新下标 ✅
- `@class_Cons` size=24（tag + xcar + xcdr）✅
- 动态分派 `fact(n-1)` 走 `vtable 下标 11` ✅
- 全局常量统一在模块级 ✅

> **踩坑记录（只有实跑才能发现）**：第一版生成的 IR 被 LLVM 拒绝——
> `%t5 = bitcast i8* i8* bitcast (%Int* @int_0 to i8*) to %Int*`（类型重复）。
> 根因：常量的 `result_` 多带了 `i8*` 前缀，而调用处又会自己加 `i8*`。SSA 寄存器（`%t5`）不带类型所以没事，**只有常量路径出错**。修复：常量一律返回**裸值**。
> 教训：语法结构"看起来对"不等于 LLVM 接受，**必须用 `llvm-as` 校验 + 实跑**。

## 7. 本文你掌握了什么 / 易错点 / 下一步

**掌握**：boxed 表示、对象布局/vtable 的 IR 落地、动态分派三段间接寻址、拆箱/装箱、if 的 phi、let 的 alloca、new 的属性初始化、case 的类 ID 分派、内建方法、runtime.c、完整运行流程。

**易错点**：
1. **SSA**：每个 `%x` 只赋值一次，需用 `phi` 合并分支，别对同一 `%x` 存两次。
2. 对象 `offset 0` 是 **tag**，属性从 `offset 1` 开始（GEP 字段下标 = 属性序号 + 1）。
3. 动态分派**多两次间接寻址**（tag→vtable→函数），静态分派直接 `call`。
4. 全局常量（`@int_*`/`@strlit_*`）必须放**模块级**，不能嵌在函数体里（实测踩坑）。
5. `isvoid` 就是 `icmp eq i8* v, null`。
6. **常量值的类型前缀**（实测踩坑）：`result_` 里常量要写成**裸值** `bitcast (%Int* @int_0 to i8*)`，由调用处自己拼 `i8*`；写成 `i8* bitcast(...)` 会产出 `bitcast i8* i8* ...` 被 LLVM 报 "expected value token"。
