## 精炼段

parser 只保证程序"语法正确"，但**不认识名字**——`x` 是变量还是方法？它指向哪个声明？这是**语义分析（semantic analysis）**的职责。核心数据结构是**符号表（symbol table）**：一张"名字 → 信息"的映射，配一个**作用域栈**（每个 `let`/`case`/方法形参引入一个新作用域）。查找规则是**静态作用域**：从最内层作用域往外找，第一个命中即结果。Cool 的语义（源自手册）规定：`self` 隐式绑定、形参/let/case 变量是词法作用域、属性在类内可见、方法名与变量名不冲突（所以需要**两套**符号表）。理解本文是理解类型检查（doc 06）的前提。

---

## 1. 语义分析的任务：parser 做不了的事

| | 语法分析（doc 03） | 语义分析（本文 + doc 06） |
|---|---|---|
| 回答 | 程序**结构**对不对 | 程序**含义**对不对 |
| 例子 | `if x then 1 else 2 fi` 结构合法 | `x` 是 Bool 吗？`x` 声明过吗？ |
| 是否认识名字 | ❌（`x` 只是"一个 ID token"） | ✅（`x` 是"第 3 行 let 声明的 Int"） |

**一句话**：parser 画出了"句子成分"，语义分析检查"这句话逻辑通不通"。

---

## 2. 符号表（Symbol Table）：名字的"户口本"

**符号表** = 记录**名字 → 信息**的数据结构。信息可以是：类型、种类（变量/方法/类）、所在作用域、内存位置等。

Cool 需要**两套**符号表（因为变量名和方法名**不冲突**，一个类里可以同时有 `x` 这个属性和 `x()` 这个方法）：

| 符号表 | 记什么 | 对应手册术语 |
|---|---|---|
| 对象环境 O | 变量名 → 类型 | object environment |
| 方法环境 M | (类名, 方法名) → 签名（形参类型列表 + 返回类型） | method environment |

> 手册原文（`refs/cool-manual-full.txt`）："Two mappings are required instead of one because object names and method names do not clash."

---

## 3. 作用域（Scope）与静态作用域

**作用域**：一个名字"在哪些地方可见/有效"的范围。

Cool 是**静态作用域（词法作用域，lexical scoping）**：名字的可见范围由**程序文本结构**决定（而非运行时调用链）。手册原文：

> "Local variables and formal parameters have lexical scope. Attributes are visible throughout a class... The binding of an identifier reference is the innermost scope that contains a declaration for that identifier, or to the attribute of the same name if there is no other declaration."

**直觉**：变量像"俄罗斯套娃"——内层能看到外层，外层看不到内层。引用 `x` 时，**从最内层往外找，第一个命中**。

### 3.1 谁引入新作用域（Cool 里）

| 构造 | 引入作用域？ | 说明 |
|---|---|---|
| 方法形参 | ✅ | 形参在方法体可见 |
| `let x : T in ...` | ✅ | x 在 let 体内（及后续绑定初始化）可见 |
| `case x : T => ...` | ✅ | x 在该分支体内可见 |
| 属性（attribute） | 半 | 属性在**整个类**可见（可被局部声明遮蔽） |
| `self` | 特殊 | **隐式绑定在每一个类** |

### 3.2 遮蔽（Shadowing）

内层声明**遮蔽**同名外层声明。Cool 的 `let` 明确支持："If an identifier is defined multiple times in a let, later bindings hide earlier ones."

---

## 4. 符号表的实现：作用域栈（Scope Stack）

用一个**栈**维护嵌套作用域：进入新作用域 `push` 一张新表，离开 `pop`；查找 `lookup` 从栈顶往栈底扫。

```
lookup(x):
  for 作用域 in 栈（从顶到底）:
    if x 在 作用域: return 它
  return "未找到"

    栈顶（最内层 let）
   ┌──────────────┐
   │ x : Int      │  ← let x : Int in ...
   ├──────────────┤
   │ y : String   │  ← 方法体
   ├──────────────┤
   │ self : SELF_TYPE │ ← 每个方法都隐式有 self
   └──────────────┘
    栈底（最外层）
```

## 5. 代码：`src/symtab.h`

```cpp
#pragma once
#include <string>
#include <vector>
#include <unordered_map>
#include <optional>

namespace cool {

// 作用域栈：维护"变量名 → 类型"的嵌套作用域
class SymbolTable {
public:
  // 进入新作用域
  void pushScope() { scopes_.emplace_back(); }

  // 离开作用域
  void popScope() { scopes_.pop_back(); }

  // 在当前（最内层）作用域声明一个名字
  void add(const std::string& name, const std::string& type) {
    scopes_.back()[name] = type;
  }

  // 从最内层往外查找；未找到返回 nullopt
  std::optional<std::string> lookup(const std::string& name) const {
    for (auto it = scopes_.rbegin(); it != scopes_.rend(); ++it) {
      auto found = it->find(name);
      if (found != it->end()) return found->second;
    }
    return std::nullopt;
  }

  // 当前是否在全局（无任何局部作用域）
  bool empty() const { return scopes_.empty(); }

private:
  std::vector<std::unordered_map<std::string, std::string>> scopes_;
};

} // namespace cool
```

**用法示意**（类型检查时，doc 06 会真正用到）：

```cpp
SymbolTable O;
O.pushScope();                       // 方法体作用域
O.add("self", "SELF_TYPE");          // self 隐式绑定
O.pushScope();                       // let 引入的作用域
O.add("x", "Int");
auto t = O.lookup("x");              // "Int"（先在内层找到）
O.popScope();                        // 离开 let
O.popScope();                        // 离开方法体
```

> **设计说明**：这里存的是 `string → string`（名字→类型名），够类型检查用；真实编译器符号表项会复杂得多（种类、定义位置、偏移量等），doc 08（运行时组织）会补充"变量在栈帧里的位置"这类信息。

## 6. 类级环境：为类型检查铺路（预告 doc 06）

除了变量作用域，类型检查还要两张**全局表**（在 doc 06 的 typechecker 里构建）：

1. **继承图**：每个类的父类；并检查——无重复类、父类存在、无继承环、`Int/String/Bool` 不能被继承、`Object/IO/Int/String/Bool` 不能被重定义。
2. **方法环境 M**：`(类, 方法名) → 签名`，含继承与重写检查（重写必须签名完全一致）。
3. **属性环境 O_C**：每个类的属性 `名字 → 类型`（含继承），按"先祖先后自身、同层按源码序"排列（这个顺序 doc 08 做对象布局时会用到）。

这些是"语义分析"的另一半——**名字解析**（把方法调用、属性引用解析到具体声明），doc 06 一并实现。

## 7. 本文你掌握了什么 / 易错点 / 下一步

**掌握**：语义分析的角色、符号表、作用域、静态作用域、遮蔽、作用域栈实现、Cool 的两套符号表、self 的隐式绑定。

**易错点**：
1. **变量名和方法名不冲突** → 需要两套符号表（O 和 M），别用一个表混着查。
2. `self` 是**隐式**绑定（不用写声明），但**不能**赋值给 self、不能在 let/case/形参里绑定 self。
3. 查找是**从内到外**第一个命中；外层不遮蔽内层（是内层遮蔽外层）。
4. `let` 的**后面绑定能看到前面绑定**的初始化（`let x<-1, y<-x+1`），实现时要注意顺序。
