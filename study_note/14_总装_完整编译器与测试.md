## 3. 自测（先自己做，再看下面答案）

**题 1（概念）**：为什么递归下降 parser 无法处理左递归文法？优先级爬升是如何绕过这个问题的？

**题 2（应用）**：写出表达式 `if c then new Cons else new Nil fi` 的类型推断过程（Cool 类型规则）。

**题 3（思考）**：运行时执行 `obj.f()`（动态分派）需要几次内存访问？为什么虚函数调用比普通函数调用慢？这与 doc 08 的哪种结构有关？

**题 4（综合）**：Cool 的 `SELF_TYPE` 解决了什么问题？在 `copy() : SELF_TYPE { self }` 里，返回类型在父类和子类中分别是多少？

---

## 4. 自测答案

**题 1**：左递归 `E → E + T` 会让"分析 E"递归地要求"先分析 E"，死循环。优先级爬升的解法：**每个优先级一层函数**，层内左结合用**循环**、右结合用**递归**、前缀用**递归**，把"优先级"编码进函数调用链——`parseAddSub` 调 `parseMulDiv`，于是 `1 + 2 * 3` 里 `2 * 3` 先被更紧的层吃掉。

**题 2**：`c : Bool`（[If] 规则要求）；`new Cons : Cons`、`new Nil : Nil`（[New] 规则）；整个 if 的类型 = `lub(Cons, Nil)`（[If] 规则）= Cons 和 Nil 的**最近公共祖先 = List**。故 `if c then new Cons else new Nil fi : List`。

**题 3**：**三次**间接访问：① 从对象读 tag → ② 从 class_meta 读 vtable 指针 → ③ 从 vtable 读函数指针。比静态调用多**两次**间接寻址，且**无法内联**（编译期不知道具体实现）。对应 doc 08 的**分发表（vtable）**结构。

**题 4**：SELF_TYPE 解决"继承时返回类型写死"的问题——`copy()` 在父类返回父类自身、在子类返回子类自身（`(new Sally).copy()` 的类型是 `Sally` 而非 `Object`）。类型规则：方法返回 SELF_TYPE 时，调用的静态类型 = **接收者的静态类型**（父类里是父类、子类里是子类）。

## 5. 学习路线回顾（你走过的路）

```
词法(正则/自动机) → 语法(CFG/递归下降/LR) → 语义(符号表/类型系统)
   → IR(三地址码/SSA) → 运行时(栈帧/对象/vtable) → 代码生成(LLVM IR)
   → 优化(数据流分析) → 寄存器分配 → 垃圾回收 → 前沿(LLVM/MLIR/TVM/JIT)
```

**核心收获**：你不仅会写编译器，更掌握了"**分析程序、转换程序、优化程序**"的通用方法论——这是 PL / 深度学习编译器 / 静态分析等方向的地基。
