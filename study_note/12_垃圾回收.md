## 精炼段

我们的 `cool_alloc` 现在只 `malloc` 从不释放——程序跑久了内存会漏光。垃圾回收（GC）就是**自动**回收不再使用的堆对象。核心思想是**可达性**：从一组**根**（栈上的变量、寄存器、全局变量）出发，沿着指针能走到的对象是"活的"，走不到的是"垃圾"。三大经典算法：**标记-清除**（mark-sweep，两遍扫描，简单但有碎片）、**复制收集**（copying，半区复制，快但浪费一半内存）、**引用计数**（每个对象计数，即时但处理不了循环引用）。现代工业（Java/Go/JS）几乎都用**分代收集**：基于"大部分对象早死"的经验规律，把堆分成新生代/老年代，新生代频繁用复制收集（快）、老年代偶尔用标记-清除。

---

## 1. 可达性：谁是垃圾？

```
根（roots）: 栈变量、寄存器、全局变量
   │
   ▼
 对象A ──► 对象B ──► 对象C
             │
             ▼
           对象D
   （对象E 没有任何人指向它 → 垃圾）
```

**定义**：从根出发能到达的对象是**活的**；不可达的是**垃圾**，可回收。

**直觉**：把内存看成"引用关系图"，从根（程序的入口可见变量）做**图遍历**（DFS/BFS），没被访问到的就是垃圾。

---

## 2. 标记-清除（Mark-Sweep）

最简单的 GC，两阶段：

1. **标记（Mark）**：从根出发 DFS，标记所有可达对象。
2. **清除（Sweep）**：遍历整个堆，回收未标记的对象，加入空闲链表。

**缺点**：① 清除阶段要扫全堆（即使垃圾很少）；② 产生**内存碎片**（回收的对象大小不一，堆变成"蜂窝"）。

**优点**：实现简单，不移动对象（适合 C/C++ 这种指针不能随意改的场景）。

---

## 3. 复制收集（Copying / Cheney 半区法）

把堆分成两个**半区**：`from` 和 `to`。对象只分配在 `from` 半区。

1. 从根出发遍历 `from` 里的活对象；
2. **复制**到 `to` 半区（紧凑排列，无碎片）；
3. 更新所有指针；
4. 交换 `from` / `to` 角色。

**优点**：① 分配快（只在 `from` 顶部 bump 指针）；② **无碎片**（复制时紧凑化）。
**缺点**：**浪费一半内存**；要**移动对象**（更新所有指向它的指针）。

**直觉**：像"搬家时只带走有用的东西，新家摆得整整齐齐，旧家整个腾空"。

---

## 4. 引用计数（Reference Counting）

每个对象带一个**计数**：被引用时 +1，引用消失时 -1，计数归零即回收。

**优点**：即时回收、实现简单。
**缺点**：① **处理不了循环引用**（A↔B 互相引用，计数永远不为 0 → 内存泄漏）；② 每次指针赋值都要更新计数，开销大。

> Python 早期就用引用计数 + 额外循环检测器兜底；Swift 用 ARC（编译期自动插入引用计数）。

---

## 5. 分代收集（Generational GC）——现代主流

**经验规律**：**大部分对象活不长**（"新生对象更可能死"），少数老对象活很久。

**策略**：按对象年龄分**代**：
- **新生代（young gen）**：频繁、快速回收（复制收集，因为大部分是垃圾，复制成本低）；
- **老年代（old gen）**：偶尔回收（标记-清除，因为老对象大多还活着）。

**关键机制**：**写屏障（write barrier）**——记录"老年代指向新生代"的指针，这样回收新生代时不用扫老年代（否则老对象可能指向新对象，漏掉就会误回收）。

> Java（G1/ZGC）、Go、JavaScript（V8）都用分代。Go 的 GC 演进（从标记-清除到并发三色标记）是理解现代 GC 的好案例。

---

## 6. 与你的背景的联系

- **vLLM / KV Cache**：你写过的 KV Cache 是**手动内存管理**（预分配、复用、淘汰）——本质是"我知道对象的生命周期，所以自己管，不靠 GC"。理解 GC 能帮你理解"为什么推理引擎要手动管理显存"（GC 的暂停和不确定性对延迟敏感场景不可接受）。
- **CUDA**：GPU 显存没有 GC，全靠手动 `cudaMalloc/cudaFree` 或内存池——你的 CUDA 经验里"显存泄漏/碎片"问题，正是 GC 想自动解决的。

---

## 7. 本文你掌握了什么 / 易错点 / 下一步

**掌握**：可达性与根、标记-清除、复制收集、引用计数、分代收集、写屏障、与 vllm/CUDA 的联系。

**易错点**：
1. 垃圾 = **不可达**，不是"被删除的"（GC 里没有显式 delete）。
2. 引用计数**处理不了循环引用**（最经典考点）。
3. 复制收集**浪费一半内存**但**无碎片**；标记-清除**有碎片**但省内存。
4. 分代 GC 的**写屏障**是保证"只扫新生代也能正确找到所有活对象"的关键。
