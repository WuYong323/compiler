## 精炼段

编译器前端（理解语言）和后端（生成机器码）之间需要一个**"通用货币"——中间表示（IR）**。有了 IR，N 种源语言 + M 种目标机器只需要 N+M 个翻译器，而不是 N×M。IR 的设计核心是**三地址码（three-address code）**：每条指令最多一个运算、最多三个操作数，像"汇编但更抽象"。现代 IR 更进一步用 **SSA 形式**：每个变量**只被赋值一次**，这大大简化了优化（常量传播、死代码消除都变得平凡）。**LLVM IR** 是这套哲学的集大成者，是 Clang/Rust/Swift 等语言的共同 IR；理解它是进入 LLVM 乃至 MLIR（多级 IR）世界的门票。

## 1. 为什么需要 IR：前端/后端解耦

```
          N 种源语言           M 种目标机器
         Cool  C  Rust      x86  ARM  RISC-V
            \   |   /          /    |     \
             v  v  v          v     v     v
            ┌─────────┐     ┌──────────────┐
            │  前端    │     │   后端        │
            └────┬────┘     └──────┬───────┘
                 └──────┬─────────┘
                        v
                   ┌─────────┐
                   │   IR    │   ← 通用中间表示
                   └─────────┘
```

**直觉**：IR 像国际贸易里的**美元**——各国（语言）先换成美元（IR），再换成别国货币（机器码）。没有统一货币，每个国家对每个国家都要单独谈汇率（N×M 个翻译器）。

**好处**：① 前端/后端独立开发、独立优化；② 优化写在 IR 上，对所有语言/机器共享；③ 错误诊断、调试信息都在 IR 层统一处理。

## 2. IR 的常见形式（全家福）

| 形式 | 代表 | 特点 |
|---|---|---|
| 语法树 AST | 早期编译器 | 贴近源语言，难优化 |
| **三地址码 TAC** | gcc RTL、LLVM IR（非 SSA 版） | 每条指令 `x = y op z` |
| **SSA** | LLVM IR、现代编译器主流 | 三地址码 + 变量只赋值一次 |
| 栈式字节码 | JVM、Python、WASM | 操作数在栈上，紧凑 |
| 图式（Sea of Nodes） | JIT（V8、Graal） | 数据流图，无严格顺序 |

**我们选 LLVM IR（文本）**：它同时是"三地址码 + SSA"，且能直接用 `lli/clang` 跑起来。

---

## 3. 三地址码（Three-Address Code, TAC）

**定义**：每条指令形如 `x = y op z`（至多一个运算符、至多三个"地址"= 变量/常量）。复杂表达式被**拆解**：

```
Cool:   a = b * c + d * e
TAC:    t1 = b * c
        t2 = d * e
        t3 = t1 + t2
        a  = t3
```

**为什么叫"三地址"**：`y op z → x` 涉及 x、y、z 三个地址（变量/常量/临时变量）。引入的临时变量 `t1, t2...` 对应寄存器或栈槽。

**直觉**：TAC 把"一句话"拆成"一串最简动作"，就像把 `2*3+4` 拆成"先 2×3 得 6，再 6+4 得 10"。

---

## 4. SSA 形式（Static Single Assignment）——现代 IR 的根基

**规则**：**每个变量在程序文本中只被赋值一次**。若某处有多个可能的来源（如 if 的两条分支），用 **φ 函数（phi function）**合并：

```
C 代码:   if (c) x = a; else x = b;  use(x);
SSA:      if c goto L1 else L2
        L1: x1 = a;  goto join
        L2: x2 = b;  goto join
        join: x3 = φ(x1, x2)     ← φ 根据"从哪条边来"选 x1 或 x2
        use(x3)
```

**为什么 SSA 让优化变简单**（关键收益，doc 10 会用）：

- **常量传播**：`x = 3; use(x)` → 直接 `use(3)`（因为 x 只赋值一次，值唯一）。
- **死代码消除**：赋值后从未被使用 → 直接删掉。
- **求值顺序不敏感**：SSA 本质是**数据流图**，指令顺序可以自由重排（对优化器友好）。

> 这是 LLVM、MLIR、TVM 等几乎所有现代编译基础设施的共同底座。**理解 SSA = 理解现代编译器的核心。**

## 5. LLVM IR 详解（我们要生成的目标）

LLVM IR 是一个**强类型、SSA、三地址码**式的中间语言。我们逐层拆解它的结构。

### 5.1 四层结构

```
Module（模块 = 整个程序）
  └─ Function（函数，如 @fact）
       └─ Basic Block（基本块 = 一串无分支的指令序列）
            └─ Instruction（指令，如 %t = add i32 %a, %b）
```

**基本块（Basic Block）**：一段**只能从开头进入、到结尾退出**的直线代码。块的最后一条必须是**终结指令（terminator）**：`br`（跳转）、`ret`（返回）等。

### 5.2 类型系统（LLVM 是强类型 IR）

```
i1    1 位整数（布尔）        i32   32 位整数
i8/i64/... 其他位宽           double  双精度浮点
i8*   指针（指向 i8）          [N x i32] 数组
{ i32, i8* }   结构体          <4 x i32>  向量（SIMD）
```

### 5.3 标识符与 SSA 规则

- **全局值**（函数、全局变量）以 `@` 开头：`@fact`、`@.str`。
- **局部值**（虚拟寄存器）以 `%` 开头：`%t1`、`%n`。
- **SSA 规则**：每个 `%x` 只能被一条指令赋值；要"修改"就造新名字（`%x1`、`%x2`）。这是**代码生成时最要注意的约束**。

### 5.4 一个完整例子（factorial）

Cool 的 `fact(n) = if n=0 then 1 else n*fact(n-1) fi` 翻译成：

```llvm
define i32 @fact(i32 %n) {
entry:
  %cond = icmp eq i32 %n, 0        ; n == 0 ?
  br i1 %cond, label %then, label %else

then:
  ret i32 1

else:
  %n1 = sub i32 %n, 1              ; n - 1
  %rec = call i32 @fact(i32 %n1)   ; 递归调用
  %res = mul i32 %n, %rec          ; n * fact(n-1)
  ret i32 %res
}
```

**逐行读**：
- `define i32 @fact(i32 %n)`：定义返回 i32 的函数，参数 `%n`。
- `icmp eq i32 %n, 0`：整数比较相等，结果 i1（布尔）。
- `br i1 %cond, label %then, label %else`：条件跳转（终结指令）。
- `call i32 @fact(i32 %n1)`：函数调用。
- 每个 `%` 变量只赋值一次（SSA）。

### 5.5 φ 函数示例（if 两个分支汇合）

```llvm
define i32 @f(i1 %c, i32 %a, i32 %b) {
entry:
  br i1 %c, label %then, label %else
then:
  br label %merge
else:
  br label %merge
merge:
  %x = phi i32 [ %a, %then ], [ %b, %else ]   ; 来自 then 取 %a，来自 else 取 %b
  ret i32 %x
}
```

## 6. 为什么我们"直接生成文本 LLVM IR"

回顾技术选型（doc 00 §6）：我们让编译器**打印 LLVM IR 文本**，而不是调用 LLVM 的 C++ API。原因：

1. **零依赖**：编译我们的编译器只需 g++，不需要装 LLVM 开发库；
2. **完全透明**：生成的 IR 就是可读文本，你肉眼就能看懂、能 debug；
3. **贴合学习**：直接面对 SSA 的"每个变量赋值一次"约束，理解最深。

> 代价是不能用 LLVM 的优化 pass（要手动调 `opt`）。但**理解层面**，手写 IR 比调 API 学到的东西多得多。真实编译器（如 Rust、Swift）用 LLVM C++ API 构建 IR，doc 13 会对比讲。

## 7. 现代工业延伸：从 LLVM IR 到 MLIR

| | LLVM IR | MLIR |
|---|---|---|
| 层级 | 单一层级（偏底层） | **多级**（可自定义 Dialect，从高层到低层） |
| 用途 | 通用编译（C/Rust/Swift） | 深度学习编译器（TensorFlow/XLA、TPU） |
| 核心思想 | SSA + 三地址码 | 同样 SSA + 三地址码，但允许**自定义指令集**（Dialect） |

**关键认知**：MLIR 的哲学 = "**编译器本身就是 SSA + pass 的组合**"，它把 LLVM IR 的思想泛化——你可以为张量运算定义 `tensor` Dialect、为 AI 芯片定义 `linalg`/`gpu` Dialect，然后在不同层级之间"降级（lowering）"。**这正是你深度学习编译器方向（TVM/XLA）的地基**，doc 13 详细展开。

**易错点**：
1. **SSA 规则**：每个 `%x` 只赋值一次——代码生成时"修改"变量必须造新名字，这是最常犯的错。
2. 基本块必须以**终结指令**（`br`/`ret`）结尾，不能"掉落到下一块"。
3. `icmp` 返回 `i1`（不是 i32），`br` 的条件必须是 `i1`。
4. LLVM 标识符：全局 `@`、局部 `%`；局部变量是**虚拟寄存器**（无限个，由寄存器分配器再映射到真寄存器）。
